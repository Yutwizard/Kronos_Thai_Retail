Problem: Ticker sanitization sprawls across ~6 sites; ranking does ~3N parquet reads.

Solution: Deepen behind one PriceStore module with memoization; single sanitize + single sanity rule.

  • locality: close-price logic lives in one module
  • leverage: Expected Return + DR Premium % share one source
  • Tests inject a fake store; no filesystem fixtures
  • Two adapters justify the seam: disk in prod, in-memory in tests

DR Execution Adapter

Strong ports & adapters

kth/trading/trade_gen.py · kth/trading/_dr_optional.py · kth_dr/ · kth/data/universe.py

Before — shallow pass-through

interface: _dr_optional passthrough

implementation: 11 lines, one lambda

Deletion test fails: interface ≈ implementation.

After — deep adapter

ExecutionResolver interface

execution_price · friction · sector · currency_group · premium_pct

implementation absorbs the 3 lambda-fallback triples + underlying→execution mapping

Problem: Last two DR display-price bugs: callers used underlying close, not execution close.

Solution: One ExecutionResolver adapter owns the underlying→execution seam; non-DR is identity inside.

  • locality: THB-vs-foreign translation in one seam
  • leverage: ranking, ticket, Position table fixed together
  • Interface shrinks; implementation absorbs the wrappers

Touches ADR-0004: adapter must keep sector and currency_group as independent pools (AND-reject), never one merged key.

One pipeline core

Worth exploring in-process

scripts/dashboard.py (cmd_generate) · kth/pipeline/daily.py · kth/backtest/walkforward.py (precompute_forecasts)

Before — two parallel pipelines

Flask cmd_generate: wipe + redo all tickers
precompute_forecasts: skip cached dates
CACHE_SLUG hardcoded ×3
calibration computed twice, mapped once

After — shared steps, thin entrypoints

ensure_data → ensure_forecasts → build_ticket
Flask + Kaggle inject loader / model / store
dashboard.py keeps HTTP thin wrappers only

Problem: Same morning shape, divergent wipe-vs-resume and sanity rules.

Solution: Extract injectable steps + one ForecastStore module.

  • locality: pipeline change made once
  • leverage: both runtimes share date/delta/calibration logic
  • Each step testable offline with fake loader
